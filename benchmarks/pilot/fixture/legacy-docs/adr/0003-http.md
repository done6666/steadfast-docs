# ADR-0003: One outbound HTTP client

- Status: accepted
- Date: 2026-05-28
- Owners: platform

## Context

Provider calls were spread across services. Each service configured its own
timeout and retry policy. During an incident one service retried a non
idempotent request and created duplicate provider charges. A second service had
no timeout and pinned connections until the pool was exhausted.

The platform team needs one place to enforce a timeout, to attach a request id
and to change the transport without touching every provider.

## Decision

All outbound HTTP goes through `packages/http/client.js`. The client sets an
abort timeout, serializes a JSON body and returns the response. Provider
adapters call the client; they do not call `fetch` directly and they do not
import an HTTP library.

A provider-specific timeout may be passed to the client. A provider-specific
retry policy lives in the adapter, not in the client.

## Consequences

- One transport to observe and to harden.
- A provider that needs a non-HTTP transport must expose an adapter behind the
  provider port, not bypass the client.
- A direct `fetch` is a review defect and a test failure.

## Alternatives considered

- Axios per service: rejected because the timeout and retry policy drift.
- A full API gateway for outbound calls: rejected as too much infrastructure for
  the current volume.

## Enforcement

`test/http-guard.test.js` scans `packages/` and fails if any file other than the
client calls `fetch`.
